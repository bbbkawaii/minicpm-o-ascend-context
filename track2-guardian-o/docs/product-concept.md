# 见微 Guardian-O 产品定义

## 1. 核心观点

Guardian-O 的创新不在于识别某个实验器材，而在于把全模态模型从“等待提问的聊天工具”变成“持续理解现场的操作教练”。它同时处理视频、语音、文本和会话历史，在正确时机主动说话，并把提醒原因转化为用户可检查的证据。除了安全风险，它还关注实验有效性：识别可能导致取样错误、污染、步骤失序、数据失真或实验失败的不规范操作，并解释“这个动作为什么会影响结果”。

## 2. 目标用户

- 需要完成实验安全训练的学生
- 负责多人实验教学的教师或助教
- 需要标准化操作演练的新员工
- 需要回顾操作过程的培训负责人

比赛 MVP 只服务“学生完成一次安全演练”这一主用户，不建设教师后台或企业管理系统。

## 3. 用户问题

- 静态手册不知道用户当前做到了哪一步。
- 指导人员无法持续观察每一位学习者。
- 普通目标检测缺少任务上下文，无法解释“为什么现在不应该这样做”。
- 部分不规范操作当下看似没有安全事故，却会破坏实验条件，造成样品污染、步骤无效、数据失真或整次实验失败。
- 操作完成后缺少可回溯的步骤、纠正记录和实验结果影响说明。

## 4. 核心闭环

```text
选择任务 → 授权音视频 → 持续观察 → 识别安全风险或结果偏差
        → 主动提醒并解释影响 → 用户打断/追问 → 纠正操作
        → 验证实验仍可继续或标记需重做 → 生成报告
```

核心功能包括：

- 任务卡理解
- 实时视频和音频输入
- 当前步骤与现场状态判断
- 不规范操作及其实验结果影响判断
- 主动语音提醒与原因解释
- 用户打断和多轮追问
- 事件去重、冷却和确认
- 纠正后的实验可继续性判断
- 证据卡时间线
- 会话结束操作报告

## 5. 比赛演练场景

演示使用安全道具，不使用真实化学品：

- 事件 A：用户开始操作但未佩戴护目镜，证明安全防护观察。
- 事件 B：任务要求蓝色标签容器，用户拿起红色标签容器；如果继续使用，可能造成取样对象错误，使后续数据无效，证明视觉、任务和实验结果影响的联合理解。
- 事件 C：用户跳过标签确认，准备进入下一步骤；助手应在不可逆操作前阻止继续，说明标签未确认会破坏样品可追溯性，并判断纠正后可以继续还是必须重做。

三个事件分别证明安全防护观察、视觉与任务联合理解、时序步骤理解和实验有效性保护。用户在事件 B 的语音提醒中打断并追问“为什么不能用这个”，助手不仅指出动作不规范，还应解释它如何导致错误结果或实验失败，证明实时交互不是预录流程。

## 6. 评审价值

| 评审方向 | Guardian-O 的证明 |
|---|---|
| 应用完整度 | 从任务开始到报告结束形成闭环 |
| 交互体验 | 主动提醒、自然语音、用户打断、即时状态反馈 |
| 全模态能力 | 视频、音频、文本输入和文本、语音输出 |
| 场景价值 | 同时减少安全风险和因不规范操作造成的实验失败、返工与无效数据 |
| 工程质量 | 独立部署、假后端、真实后端、测试和可观察性 |
| 演示质量 | 三个明确事件，一镜到底，前后状态可见 |
| 复现可行性 | 标准任务卡和安全道具可在官方环境重复 |

## 7. 明确不做

- 不宣称替代专业安全人员。
- 不对真实危险操作作自动授权。
- 不使用真实危险材料进行比赛演示。
- MVP 不做多实验平台、教师后台、多人识别或设备控制。
- 不以硬编码视频或预录语音冒充实时模型能力。

## 8. 评委陈述

> 见微 Guardian-O 是运行在昇腾 NPU 上的全模态实验操作伴随助手。它能够持续观察实验现场、听懂用户问题，在关键时刻主动语音提醒，识别可能导致安全事故或实验失败的不规范操作，解释这些操作为什么会影响结果，并支持用户随时打断，最终形成可追溯的操作报告，让实验指导从静态手册升级为真正理解现场、保护实验有效性的实时教练。
