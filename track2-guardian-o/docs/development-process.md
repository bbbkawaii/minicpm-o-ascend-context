# Guardian-O 协同开发流程

## 阶段 0：产品和协议冻结

产物：产品定义、90 秒脚本、事件结构、任务卡样例、结果影响规则和报告样例。

通过条件：所有协作者能用同一组术语描述主流程；MVP 只有一个实验场景和三个事件；每个结果相关事件都明确潜在后果、可逆检查点和纠正后状态。

## 阶段 1：Mock Web MVP

产物：摄像头授权、主界面、事件时间线、实验有效性状态、字幕、语音占位、用户打断按钮和报告页面。

通过条件：不需要 NPU，在普通电脑上能够完整演示主流程；刷新页面可以重新开始；错误状态可见。

## 阶段 2：后端会话与事件策略

产物：会话状态机、任务卡加载、事件协议、去重/冷却、结果影响与可恢复性判断、报告生成、Mock WebSocket。

通过条件：自动测试覆盖会话开始、事件触发、重复事件抑制、可纠正风险、不可逆失败状态、打断和会话结束。

## 阶段 3：Stable 模型接入

产物：赛道二自己的 MiniCPM-o 适配器、分段视频/音频请求、流式文本/语音输出和错误降级。

通过条件：在声明环境内连续完成三次完整演练；模型服务重启后可恢复；不需要赛道一目录。

## 阶段 4：Realtime 模式

产物：实时音视频、主动提醒、语音打断和端到端延迟指标。

通过条件：完成至少 20 次脚本化演练，统计事件成功率、误提醒、结果影响解释正确率、实验有效性状态正确率、打断成功率和首响延迟。

## 阶段 5：昇腾复现

产物：环境清单、安装脚本、启动命令、健康检查、最小复现步骤和已知问题。

通过条件：从干净官方环境按文档完成部署；Stable 模式必过，Realtime 模式记录结果和限制。

## 阶段 6：提交材料

产物：Web Demo、项目说明、PPT、90 秒演示视频、完整演示视频、部署文档和测试证据。

通过条件：由未参与开发的协作者按说明完成一次复现；提交包不含密钥、权重或个人数据。

## 并行工作建议

| 工作流 | 可并行内容 | 依赖 |
|---|---|---|
| UX | 页面、状态、证据卡、报告 | 阶段 0 协议 |
| Backend | 会话、事件策略、Mock 服务 | 阶段 0 协议 |
| Model | Stable/Realtime 适配与提示 | 事件协议 |
| QA | 脚本场景、错误注入、复现检查 | 每阶段接口 |
| Submission | 项目叙事、PPT、视频分镜 | 产品定义，可提前开始 |

每个 PR 只属于赛道二，且应尽量只影响一个工作流。
