# Guardian-O 90 秒演示脚本

## 道具

- 护目镜
- 红色与蓝色标签的透明空容器
- 一张任务卡
- 普通桌面和摄像头
- 不使用任何真实危险材料

## 分镜

| 时间 | 操作 | 系统证明 |
|---:|---|---|
| 0–10 秒 | 打开 Guardian-O，选择“实验室安全演练”，展示服务运行在昇腾环境 | 可运行性、环境 |
| 10–20 秒 | 展示任务卡并开始会话 | 文本/OCR、任务理解 |
| 20–35 秒 | 未佩戴护目镜，伸手拿器材 | 持续视频理解、主动提醒 |
| 35–45 秒 | 佩戴护目镜，证据卡变为“已纠正” | 状态闭环 |
| 45–57 秒 | 故意拿红色标签容器 | 视觉、任务与步骤联合理解 |
| 57–69 秒 | 助手提醒“继续使用会导致取样对象错误，本次结果将无效”；用户在助手说话时打断：“为什么会导致实验失败？” | 结果影响解释、音频理解、打断、上下文回答 |
| 69–80 秒 | 换成蓝色容器并完成标签确认；页面从“结果存在风险”恢复为“可继续” | 纠正确认、实验有效性状态闭环 |
| 80–90 秒 | 结束任务，展示操作报告中的不规范操作、潜在后果、纠正状态和延迟指标 | 工程证据、实验有效性保护、可追溯性 |

## 必须一镜到底证明的内容

- 摄像头画面确实实时变化。
- 用户没有先点击“触发提醒”按钮。
- 助手不仅指出拿错容器，还解释继续操作为什么会使实验结果无效。
- 打断发生在助手语音尚未结束时。
- 用户纠正后，页面重新验证并更新实验有效性状态，而不是直接假定已恢复。
- 证据卡与报告来自本次会话，且包含不规范操作、结果影响和纠正状态。
- 页面明确显示当前是 Mock、Stable 还是 Realtime 模式。

## 失败兜底

- Realtime 不稳定：切换 Stable，仍完成全部业务闭环，并说明实验能力限制。
- 音频回声影响打断：使用耳机，并保留界面上的打断状态证据。
- 某个视觉事件未触发：保持道具位置、光照和任务卡格式一致；不得用隐藏按钮伪造模型事件。
