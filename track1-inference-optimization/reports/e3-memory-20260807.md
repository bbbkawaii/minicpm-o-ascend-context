## Findings

1. **B1 (reduced budgets) is clearly worse**: throughput drops to 3.05-3.46,
   conc-8 TTFT degrades to 1.23s. Reducing both cards' budgets starves the
   pipeline. Reject.

2. **B2 / B4 are equivalent to baseline** (within noise): throughput 4.5-4.6,
   TTFT ~93ms conc4 / ~870ms conc8. HBM shifts as expected but no perf change.

3. **B3 (talker bias 0.58) is marginally best**: conc4 throughput 4.68 (+3.5%
   over B0's 4.52), TTFT 87ms (vs 96ms, -9%), conc8 also slightly better
   (4.73, 849ms). The talker stage on device 1 gets more headroom, though it
   sits idle for text-only requests.

   - p50 throughput +3.5% **exceeds the 3% screening threshold** (A1).
   - TTFT -9% exceeds 5% p95 threshold.
   - BUT this is text-only; talker bias likely matters more for audio.

## Conclusion

**B3 (0.90/0.58/0.32) is a candidate**: marginal but above-threshold gains on
text. It should be re-validated with audio and the C1/C2 correctness gates
before adopting. B1 is rejected; B2/B4 are noise.

The conc-8 TTFT cliff persists across ALL memory budgets — consistent with E2,
the cliff is not memory-bound either. It is a scheduler/backpressure issue
(→ P1 profiler work).

## Caveats

- Text-only benchmarks; audio memory behavior untested (talker/codec matter
  there).
- B3's gain is +3.5% throughput / -9% TTFT — above threshold but small;
  needs a second confirming round per the plan's 2-of-3 rule.
