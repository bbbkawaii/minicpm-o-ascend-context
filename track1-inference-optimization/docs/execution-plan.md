# 赛道一执行计划

## 目标

在官方统一昇腾环境中建立可复现的 MiniCPM-o 4.5 vLLM-Omni 服务，先通过效果与稳定性校验，再围绕 TTFT、单 chunk latency、E2E latency、吞吐、并发和资源利用率做有证据的优化。

## Gate 0：规则与环境冻结

- 确认报名赛道、截止时间、正式硬件和提交规范。
- 获取官方 starter kit、镜像 tag、CANN/驱动版本和评测脚本。
- 保存镜像 digest、模型 revision、vLLM-Omni 与 vLLM-Ascend commit。

退出条件：任何成员都能从记录的信息恢复出相同环境。

## Gate 1：Ascend smoke

- text-only 请求成功。
- 连续运行 20 次无崩溃、无空响应。
- 保存服务日志、`npu-smi info` 和冒烟结果。

退出条件：官方环境中存在一条最短、稳定、可复现的服务路径。

## Gate 2：模型能力与正确性

- 文本输出。
- 文本 + 24 kHz 语音输出。
- 图像、音频、视频输入分别通过最小样例。
- Daily-Omni 使用 `enable_thinking=false`，确保答案提取口径正确。

退出条件：所有比赛要求的模态均可运行，且效果不低于官方门槛。

## Gate 3：性能基线

- 单请求 TTFT、chunk latency、E2E。
- 并发 1/2/4/... 下的吞吐与失败率。
- NPU 利用率、显存/内存峰值。
- 30 分钟以上稳定性运行。

退出条件：生成第一版完整基线报告，后续优化均能与其公平比较。

## Gate 4：优化实验

优先顺序：

1. deploy config 与三阶段内存预算。
2. scheduler、batch、并发和请求形状。
3. Thinker/Talker/Code2Wav 流水线重叠与 chunk 策略。
4. KV cache、图模式与平台适配。
5. 在效果校验可控后再做量化。
6. 最后考虑 Ascend C 自定义算子。

每个实验只修改一个主要变量，并记录假设、改动、命令、三轮数据、正确性结果和结论。

## Gate 5：提交与上游 PR

- 提交包可在干净环境一键复现。
- 性能报告包含原始基线、优化后结果和失败实验。
- PR 保持小而明确，写清硬件、版本、验证命令和前后数据。
- Demo、PPT 和演示视频使用同一套最终配置。
